# Данные → визуализации → дашборд

Основной сценарий с 22 сентября 2026 года использует workflow v3 и самостоятельные визуализации.

## Сборка вручную

1. Откройте проект и создайте граф. Добавьте Excel Source, выберите лист и подготовьте данные
   обычными преобразованиями. Группировку, сумму, долю и ранг задавайте в графе.
2. В разделе «Публикации и фильтры» выберите выход таблицы или скаляра, задайте понятное имя
   и нажмите «Опубликовать результат». Это ссылка на выход, а не дополнительная нода.
   Настройки отдельной публикации раскрываются по её названию.
3. Для периода в «Общих фильтрах данных» выберите выход подготовленной таблицы **до итогов**,
   поле date/datetime и сохраните привязку. Укажите часовой пояс данных, если он отличается
   от Europe/Moscow. Все публикации этого графа наследуют общий профиль; неподключённые ветки
   явно отмечаются в списке покрытия на дашборде.
4. Для переходов добавьте именованный отбор и его поле/точку применения. Отбор услуги
   размещайте после вычислений знаменателей и рангов. В нужной публикации укажите поле
   перехода. Идентификаторы колонок выбираются по названиям, JSON редактировать не требуется.
5. Откройте раздел проекта «Визуализации», нажмите «Создать визуализацию», выберите публикацию, тип и поля.
   Предпросмотр не сохраняет документ. KPI принимает скаляр или поле таблицы с одной строкой;
   несколько строк требуют явной агрегации. Пустая таблица показывает отсутствие данных.
6. Создайте или откройте дашборд. Визуализация появляется в его библиотеке и может использоваться на нескольких
   дашбордах. Кнопка «Добавить виджет» размещает её; перемещение и изменение размера выполняются
   на дашборде. Сохраните расположение. Создание из окна дашборда сразу добавляет размещение
   в его несохранённый черновик.
7. Включите «Общий фильтр периода». Доступны произвольный диапазон, текущий месяц, квартал,
   год и весь период. Изменение периода обновляет результаты, а не ревизии расчётов.
8. В виджете откройте «Настроить переход»: выберите дашборд и поля выбранной записи.
   Для известных смысловых полей предлагается соответствие. Можно передавать константу
   или текущее значение. Период и совместимые значения наследуются; выбранная запись заменяет
   одноимённые значения. «Только выделять» сохраняет остальных участников сравнения.

«Настройки» редактируют общий документ визуализации. Перед сохранением показывается список
использующих его размещений. Для независимого оформления нажмите «Независимая копия».
Используемую визуализацию нельзя удалить, пока её размещения не убраны. «Открыть расчёт»
ведёт к опубликованному выходу, а не к удалённой ноде диаграммы.

## Правила периода и ошибок

Обе календарные даты включаются целиком. Для datetime используется начало первого дня и
исключительная граница начала следующего дня после конца диапазона в часовом поясе данных.
UTC и наивные Excel datetime проверены отдельно. Null-даты исключаются при активном периоде;
ошибочные строковые даты требуют явного Convert Types. Обратный диапазон отклоняется.

Результат сообщает ревизии графа и визуализации, применённые ограничения и неподключённые
фильтры. Запрос предыдущего URL-контекста не подменяет текущий результат. Во время обновления
старый результат не выдаётся за новый. Ошибка одного виджета не блокирует соседние.

## Финансовый проект

Проект `908f1522-f6cd-42e4-93e0-0a59ae0749e8` преобразован после резервного копирования.
Все 53 визуализации и 55 размещений сохранили ID. Удалены 53 ноды отображения и 30 ненужных
переходников field_scalar. Остаются 142 ноды, 187 связей, семь блоков и книга.
Публикаций 28: несколько визуализаций используют один результат.

Равенства параметрических фильтров перенесены в настройки контекста. На прежнем месте
остаётся обычный Select Columns с прежним ID — стабильная граница отбора, не финансовый
вычислитель. Другие вычисления, формулы и сортировки сохраняются. Все 164 среза и 1551
страница результатов сверены с исходными показателями, форматами, рядами и выделением.

В финансовом Excel нет дат. Период на нём не имитируется. Отдельная синтетическая книга
`fixtures/excel/monthly-sales.xlsx` содержит январь, февраль, март и запись без даты:
итог всего набора 210, января 30, февраля 70. Браузерная проверка собирает публикации,
диаграмму и скалярный KPI через UI, связывает период один раз и проверяет URL/перезагрузку.
Дополнительная таблица проверяет настройку перехода через UI с автоматическим предложением
смыслового поля. Отложенные ответы марта не подменяют уже открытый февральский срез.

## Проверка удобства

Подтверждено уменьшение графа на 83 ноды и 134 связи. Нода диаграммы и её три подключения
для стандартной диаграммы больше не нужны. Привязка даты настраивается один раз для общего
профиля, а не на каждом графике. При этом публикация добавляет отдельный шаг и оператор
по-прежнему должен правильно выбрать границу применения контекста. Это требует понимания
расчёта; автоматически угадывать её небезопасно.

Время работы человека, число его ошибок и потребность в подсказках ещё не измерены.
Процент ускорения не заявляется. Для измерения используйте существующий операторский
протокол и одинаковые задания/данные до и после изменения интерфейса.

## Границы первой версии

- Нет общего выпадающего фильтра категорий и взаимной фильтрации диаграмм кликами.
- Контекст задаётся на выходе конкретной таблицы; разные ветки не сопоставляются по номеру строки.
- Переходы между разными источниками требуют явного согласования смысловых полей.
- Автопреобразование v2 диаграммы с ещё не добавленным в таблицу выражением отклоняется:
  сначала выполните Append field. Произвольная миграция не создаёт скрытых расчётов.
- Библиотека размещает визуализации кнопкой; перетаскивание доступно уже размещённым виджетам.
- Прежние browser-сценарии создания chart nodes описывают исторический интерфейс;
  основной сценарий проверяют `publications`, `published-period`, `published-financial`.
