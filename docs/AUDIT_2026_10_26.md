# Аудит Node BI — 26 октября 2026

Дополнение после аудита: ADR-214 заменяет прежнее ограничение на правку `data_example`.
Теперь исходные ячейки сложного XLSX редактируются прямо в браузере, с серверным пересчётом
формул. Сценарий и актуальные ограничения описаны в [руководстве](REPORT_CYCLE.md).

## Результат и границы

Проверены код, контракты, основные пользовательские пути, зависимости и обслуживание локального
стенда. Найденные ниже дефекты исправлены; обновление развёрнуто на корпоративном демо3030/8030.
Постоянные проекты и исходные данные для тестов не изменялись. Это технический аудит и регрессия,
не независимая сертификация безопасности/доступности или завершение всей программы R0–R6.

- Backend:1545 тестов прошли,32 пропущены; добавлены3 проверки редактора. PostgreSQL:52 теста миграций/конфликтов/
  обновления/редактирования плюс4 проверки нового редактора и миграций прошли отдельно.
  Это не полная PostgreSQL-матрица. Первый запуск до готовности временной БД дал4 ошибки
  подключения; после readiness повторный прогон прошёл. Ошибки не скрывались изменением тестов.
- Frontend:682 теста прошли после исправлений, включая новые проверки точности ревизии,
  потерянного ответа, отмены сеанса, удаления проекта и TSV. Типы, линтеры, OpenAPI и
  production build проверены. GitHub Actions workflow подготовлен, но удалённый запуск не выполнялся.
- Все9 живых дашбордов открываются без JavaScript-исключений; детальные ОПиОП без контекста
  требуют выбора, а не подставляют нули. Каталог проектов на390px не имеет горизонтального выхода.
- Восстановление резервной копии в отдельную PostgreSQL17 БД вернуло4 проекта,9 дашбордов,
  77 виджетов и79 визуализаций. Все15 ссылок на данные и15 файловых хешей совпали; схема0012.
- Нормализация100000×3 точных decimal:0,026 с холодно/0,022 с повторно, результат4,58 МиБ Polars.
  Широкий случай1000×100:0,030/0,029 с. Это локальный замер одного этапа, не скорость всего импорта
  и не полный пик памяти: Python tracemalloc не измеряет native-память Polars.
- npm audit:0 известных записей, включая dev; OSV:0 для35 указанных runtime-версий Python на дату
  проверки. Это не анализ ОС контейнеров, не пентест и не гарантия отсутствия будущих уязвимостей.

## Обслуживание

Из корня: `powershell -NoProfile -File scripts/Update-NodeBI.ps1`. Предварительная проверка —
`-CheckOnly`; просмотр действия — `-WhatIf`. По умолчанию только Demo, Main выбирается явно.
Скрипт обновляет текущую рабочую копию, не выполняет git pull/reset и не удаляет тома.
Сборка завершается до остановки. Копия включает БД и файлы при приостановленном API/UI,
манифест и SHA-256. До развёртывания ошибка возвращает исходные контейнеры; после начала
развёртывания не выполняется опасное автоматическое восстановление/понижение схемы.
Подробности и восстановление в отдельном окружении: [README](../README.md).

## Оставшиеся ограничения и следующий приоритет

1. Полная браузерная работа с `data_example` требует настоящего Excel-совместимого пересчёта.
   Книга содержит25 листов и13219 формул. Существующий путь скачивания/замены сохраняется;
   включение простого редактора не решает эту задачу безопасно.
2. Завершить всю PostgreSQL-матрицу, автоматические браузерные end-to-end сценарии и отдельный
   тест перезапуска БД. Выполненный аудит не выдаёт непроверенные32 базовых skip за успех.
3. Провести независимые проверки WCAG2.2 AA, экранного диктора и сценарии с экономистами.
   Улучшенный контраст токенов и технические тесты не заменяют их.
4. Нагрузочная приёмка полного импорта/графа/дашборда и native-памяти на100000 строк, отдельно
   широкие и сложные Excel-книги. Текущий быстрый замер относится только к нормализации.
5. Удалённое размещение, авторизация, роли и многопользовательская защита не входят в локальный
   MVP. Нельзя просто открыть нынешние порты в интернет. Базы/копии с ОПиОП — частные данные.
6. Отдельно планировать PostgreSQL major upgrades и обновление digest базовых образов;
   скрипт обновляет приложение, не переносит базы между версиями PostgreSQL.
