# Проверка ручной работы оператора

Статус: протокол подготовлен 2026-09-15; участников и результатов пока нет.
Использовать отдельную копию проекта, не изменять принятый эталон. Старый интерфейс
для базового замера доступен в Git на коммите 8c829a3; запускать его отдельно с копией
БД/хранилища. Не откатывать рабочую БД и не запускать старую версию поверх неё.

Участники: 3–5 аналитиков, знакомых с таблицами и группировками, но не с реализацией
Node BI. Не выдавать тестовые рецепты или ID узлов. Дать описание показателей и Excel.
Для сравнения старого и нового интерфейса использовать эквивалентные задания с другими
полями/срезами; чередовать порядок версий, чтобы уменьшить влияние обучения.

| Задание | Проверка результата |
| --- | --- |
| Найти расчёт доли услуги и объяснить знаменатель | Итог класса вычисляется до отбора услуги |
| Добавить долю в классе и диаграмму сравнения | Смена услуги не уменьшает население сравнения и знаменатель |
| Добавить статью выбранного вида затрат | Стабильная идентичность, пропуски обработаны явно, нет дублей |
| Изменить поле группировки | Участник находит зависимые результаты и устраняет ошибки схемы |
| Настроить переход из строки к услуге | Передан ID, восстановлены класс и URL-срез |

На каждое задание фиксировать: время начала/конца, успех, ошибочные результаты,
подсказки ведущего, переключения страниц, ручной ввод технических ID, комментарий
участника. После лимита 20 минут фиксировать незавершённость, не записывать её как успех.
Не подсказывать расположение контролов до фиксации самостоятельного результата.
После задания попросить объяснить логику и оценить сложность по шкале 1–7.

Критерии будущей приёмки: минимум 4 из 5 выполняют задания без разработчика,
медианное время меньше базового на 40%, нет незамеченных ошибок знаменателя и ручного
ввода ID. При трёх участниках результаты считать предварительными. Сохранять исходные
замеры, а не только среднее; ошибки расчётов важнее скорости. Автотесты оцениваются
отдельно и не засчитываются как исследование с операторами.
