# Проверка ручной работы оператора

## Действующий протокол: регулярный выпуск, 2026-09-24

Этот протокол заменяет задания и целевые показатели прежнего протокола ниже.
Переходы между дашбордами не входят в испытание. Участники пока не привлечены;
автотесты и прохождение разработчиком не засчитываются как результаты экономистов.

Пять экономистов выполняют на копиях финансового и синтетического многокнижного отчётов:

1. Обновить две книги одним комплектом, заметить переставленное и переименованное поле,
   подтвердить соответствие по названиям и примерам. Действующий дашборд до применения
   должен сохранять прежние показатели.
2. Добавить новый период. Обнаружить повторный файл и исправить уже существующий период,
   не создавая двойного учёта и не меняя формулы.
3. Найти причину расхождения: несовпавший ключ Join, повтор ключа, пропуск обязательного
   значения и контрольная сумма с явно заданным допуском. Открыть соответствующую ноду.
4. Применить исправленное обновление, проверить дашборд и зафиксировать выпуск с комментарием.
5. Изменить рабочий проект, убедиться в неизменности выпуска, восстановить его в отдельный
   проект. Подготовить откат данных и объяснить, почему он не откатывает формулы.

Для каждого задания записать время, число действий, ошибки данных, обращения за помощью,
результат и уверенность пользователя. Подсказки давать только после фиксации самостоятельного
исхода. Цель: не менее четырёх самостоятельных успешных прохождений из пяти и ни одной
незамеченной ошибки данных. Невыполненное задание не записывать как успех.

Сравнивать с предыдущим интерфейсом на эквивалентных наборах и менять порядок версий между
участниками. Если старый интерфейс не поддерживает выпуск, сравнивать достижение той же цели
его доступными средствами и отдельно отметить различие функций. Процент ускорения заранее
не задавать. Публиковать индивидуальные результаты, медиану и ошибки, а не только среднее время.
До реальных книг второго отчёта предметная приёмка касается только синтетического набора.

## Архив предыдущего протокола — не критерии этой итерации

Статус: протокол подготовлен 2026-09-15; участников и результатов пока нет.
2026-09-22: техническая сборка нового полевого проекта и структурное сравнение описаны
в FIELD_FINANCIAL_REVIEW.md. Они не заменяют испытание с участниками. Сохранение старой
реализации больше не является продуктовым требованием; при отсутствии доступного старого
стенда измерять абсолютное время/успешность и не заявлять сравнительный процент ускорения.
Использовать отдельную копию проекта, не изменять принятый эталон. Старый интерфейс
для базового замера доступен в Git на коммите 8c829a3; запускать его отдельно с копией
БД/хранилища. Не откатывать рабочую БД и не запускать старую версию поверх неё.

Участники: 3–5 аналитиков, знакомых с таблицами и группировками, но не с реализацией
Node BI. Не выдавать тестовые рецепты или ID узлов. Дать описание показателей и Excel.
Для сравнения старого и нового интерфейса использовать эквивалентные задания с другими
полями/срезами; чередовать порядок версий, чтобы уменьшить влияние обучения.

| Задание | Проверка результата |
| --- | --- |
| Найти расчёт доли услуги и объяснить знаменатель | Итог класса вычисляется до отбора услуги |
| Добавить долю в классе и диаграмму сравнения | Смена услуги не уменьшает население сравнения и знаменатель |
| Добавить статью выбранного вида затрат | Стабильная идентичность, пропуски обработаны явно, нет дублей |
| Изменить поле группировки | Участник находит зависимые результаты и устраняет ошибки схемы |
| Настроить переход из строки к услуге | Передан ID, восстановлены класс и URL-срез |

На каждое задание фиксировать: время начала/конца, успех, ошибочные результаты,
подсказки ведущего, переключения страниц, ручной ввод технических ID, комментарий
участника. После лимита 20 минут фиксировать незавершённость, не записывать её как успех.
Не подсказывать расположение контролов до фиксации самостоятельного результата.
После задания попросить объяснить логику и оценить сложность по шкале 1–7.

Критерии будущей приёмки: минимум 4 из 5 выполняют задания без разработчика,
медианное время меньше базового на 40%, нет незамеченных ошибок знаменателя и ручного
ввода ID. При трёх участниках результаты считать предварительными. Сохранять исходные
замеры, а не только среднее; ошибки расчётов важнее скорости. Автотесты оцениваются
отдельно и не засчитываются как исследование с операторами.
