# Функциональные ноды: утверждённый план и состояние реализации

Дата: 2026-09-21. Обновлено: 2026-09-22. Статус: F1 завершён; F2 ожидает операторскую приёмку, F3 в работе.
Первая версия редактора доступна через «Новая полевая схема»; руководство — FIELD_EDITOR_GUIDE.md.
2026-09-22: добавлен каталог книг и листов с поиском, добавлением кнопкой/переносом мышью
и повторным открытием настроенного узла без дублирования. Карточки книг на холсте поддерживают
полевые подключения, сворачивание, отделение листа кнопкой/переносом и возврат с сохранением
ID/связей; состояние сохраняется общей ревизией графа (ADR-094).

## Цель

Собирать расчёты проводами между полями, видеть источники и результаты, сворачивать
законченные участки в раскрываемые составные блоки. Книга Excel показывает листы и поля;
используемый лист остаётся самостоятельным источником с собственной конфигурацией чтения.
Перетаскивание листа создаёт представление, а не копию данных. Настройки диаграмм остаются
в графе; dashboard ссылается на визуализации. Существующий финансовый проект не преобразуется.

## F1 — контракты и выполнение

Реализован первый внутренний слой:

- Значения TableValue, FieldValue, ScalarValue и контекст workflow / узел / выход.
- Выбор поля по стабильному column_id, в том числе по схеме без чтения строк.
- Арифметика, сравнения, AND/OR/NOT через общий безопасный компилятор формул.
- Константы и типизированные параметры с существующей проверкой типов и defaults.
- Добавление поля, фильтрация по булевому полю, явная сумма в скаляр.
- Проверка контекста строк, ограничение сложности выражений, политики null и деления на ноль.
- Проверки арифметики сохраняются при последующем сравнении: infinity не превращается
  незаметно в допустимый предикат. Числовая арифметика и сумма используют Float64;
  сравнение двух целых не округляет идентификаторы через Float64.
- Старый исполнитель адаптирован к именованному табличному выходу без копирования данных;
  preview визуализаций без выходных портов сохранён.
- PUT графа принимает явный format_version (по умолчанию 1). Повышение до 2 подчиняется
  обычному CAS; старый клиент не может перезаписать v2 даже с актуальной ревизией.
  Неизвестные поля черновика v2 отклоняются.
- Полевые связи сохраняют source_column_id в API, БД и модели графа (миграция 0007).
  В v1 отсутствующее поле не добавляется в JSON. Откат миграции запрещён при наличии
  полевых связей, чтобы не потерять их смысл. Типизированное выполнение подключено:
  schema/preview проверяют типы и контекст строк; динамические схемы требуют выполнения ветки.
  Метаданные контейнеров входят в API v2 по ADR-092; классический редактор остаётся редактором v1.

Диагностика F1 завершена по ADR-098–100:

Ошибки сохраняют вход, настройку либо именованный выход. Актуальные ошибки схемы и preview
подсвечивают соответствующие элементы инспектора. Смена графа/параметров/выхода сбрасывает
устаревшие результаты. Сообщения полевых операций доступны на русском, английском и татарском.

По ADR-092 добавлены типизированные presentation.workbooks и presentation.blocks, миграция 0008.
Сохраняются названия, положения, сворачивание, состав узлов, вынесенные листы и публичные порты.
Граф остаётся единственным источником вычислений; порты ссылаются на реальные узлы и column_id.
Границы блоков проверяются при сохранении с обычной ревизией. Пропущенное presentation сохраняет
прежнее значение; явное {} распаковывает контейнеры. Пустой v1 JSON не меняется. Интерфейс книг
и undo реализованы в F2; первая версия упаковки блоков и их граничных портов добавлена по ADR-101.

По ADR-091 Pivot работает в смешанной типизированной ветке: после проверки входов
выполняется только участок до Pivot, затем его реальные поля доступны дальнейшим связям.
Узлы с известной схемой по-прежнему не требуют чтения строк для вывода схемы. Смена параметра
может удалить категорию Pivot — подключение исчезнувшего поля явно становится ошибочным.
Проверены повторные Pivot, кэш источника, ограничения размера и ошибки предыдущих вычислений.

Выполнено по ADR-090: общий TypedNodeExecutor, именованные схемы и маршрутизация,
совместная работа со старым Group By, preview поля/скаляра с выходом, ревизией и параметрами.
Ключи кэша учитывают выход, column_id и используемый параметр; доступность источника
проверяется до выдачи кэша. Выражения не превращаются в отдельные таблицы на каждом проводе.
Каталог с format_version=2 возвращает scalar_constant, scalar_parameter, field_arithmetic,
field_compare, field_logical, append_field, field_filter, field_sum. Обычный каталог не изменён.
API проверен с настоящей Excel-книгой; приёмка нового UI описана ниже отдельно.

## F2 — книга, карточки и просмотры

Реализована первая часть по ADR-093: отдельный v2-режим, поля на карточках, восемь форм
полевых операций, соединение перетаскиванием и через списки, автосохранение, история и A/B.
В браузере собирается Excel → умножение → добавление поля → сумма, без ID/JSON.
Проверяются смена языков/тем, отмена/повтор, перезагрузка, задержка сохранения и две вкладки.
Локальные черновики изолированы по режимам. Схемы запрашиваются с параметрами просмотра;
неполная новая нода не скрывает поля готовых источников. Изменения ревизии/параметров/выхода
не позволяют показать запоздавший preview как текущий. Новые UI-строки переведены на три языка.

Карточка книги, перенос и возврат листов, сохранение и undo реализованы по ADR-094.
Подсветка входов и явных путей через полевые выражения реализована по ADR-095; происхождение
полей через табличные преобразования не предполагается. Меню операций по переносу выхода и
создание узла с подключениями одним действием реализованы по ADR-096. По ADR-097 добавлены
виртуальная прокрутка неподключённых полей, компактные карточки большого графа и поиск узлов.
Подключённые/выделенные поля закреплены вне прокрутки. Проверен синтетический граф из 168 узлов
с настоящей сгенерированной книгой на 1024 поля; остаётся операторская приёмка финансовой копии.

- Отдельный режим редактора. Книга → листы → поля, перенос листа на холст.
- Настоящие полевые провода, подсказки совместимости и предложения Join для разных контекстов.
- Компактная/раскрытая карточка и инспектор выбранной ноды; смысл операции вместо общего описания.
- Подключённые поля видимы; поиск и виртуализация остальных. Тип обозначается текстом и значком.
- Создание, переподключение, вставка — одна операция undo. Альтернатива перетаскиванию через форму.
- Два закрепляемых просмотра A/B по запросу; устаревшие результаты явно помечены.

## F3 — составные блоки и визуализации

Первая поставка: выбор узлов по именам, упаковка и распаковка, карточка с настоящими публичными
подключениями, раскрытие на общем холсте, возврат, переименование и дополнительный выход.
Операции используют существующую историю/CAS; исходный граф и ID не копируются. Проверены
переподключение свёрнутого блока, отмена/повтор, внутреннее редактирование и восстановление.
Управление составом/публичными портами и прямые входы визуализаций ещё не завершены.

- Один уровень блоков, публичные порты ссылаются на реальные внутренние подключения.
- Упаковка/распаковка сохраняется атомарно и не меняет ID, вычисления или связи dashboard.
- Вход и выход из блока через навигацию; книга не входит в составной блок.
- Категория/значение для Bar Chart и скаляр для KPI; без скрытых агрегаций.
- Вложенность, связанные шаблоны и библиотека блоков отложены.

## F4 — приёмка

Через интерфейс собрать Excel → Количество × Цена → Выручка → Фильтр → Group By →
Bar Chart + KPI → Dashboard. Без JSON и технических ID. Проверить сохранение и перезапуск,
две вкладки, медленные ответы, undo, переименование/удаление полей, большую книгу и граф
из 168 узлов. Старые проекты проверять на копиях; сравнить шесть дашбордов в 164 срезах.
Проверить три языка, обе темы, backend/frontend/PostgreSQL, сборку и браузерную приёмку.
Человеческое удобство измерить по docs/UX_OPERATOR_PROTOCOL.md; ускорение пока не измерено.

Не считать вычислительные функции готовыми пользовательскими нодами до их регистрации,
сохранения, UI-настройки и прохождения сквозного сценария.
