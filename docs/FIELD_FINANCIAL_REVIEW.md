# Финансовый дашборд на полевых нодах: результат и оценка

Дата: 2026-09-22. Новая конфигурация проекта, не специальный финансовый backend.

Проект: «Финансовая аналитика — полевые ноды».
Идентификатор: `908f1522-f6cd-42e4-93e0-0a59ae0749e8`.
Workflow: `b5daab58-f13b-4de1-bf90-980060fb919a`, формат 2.
В проекте сохранены шесть экранов: сводка, класс, услуга, вид затрат,
вид затрат в классе, вид затрат услуги. Чтение Excel, Filter, Group By,
Window, Unpivot, Join и остальные табличные операции работают через общий движок.

Все 27 Calculated Column заменены парами «Выражение над полями → Добавить поле».
Все 10 Bar Chart подключены через table/category/value. Все 30 KPI используют
скаляр от узла «Единственное значение», включая текстовые названия и готовые итоги.
Оставшиеся Table и Donut используют обычные табличные входы. Семь составных блоков
и карточка книги организуют представление; внутренние операции доступны для изменения.

Сборка выполнена через публичные API сохранения проекта, источника, workflow и dashboard.
Она автоматизирована, поэтому не доказывает, что человек соберёт весь проект быстро
или без помощи. Исходный проект используется для численной сверки. Удаление его
и сброс базы не выполнялись. Пользовательская книга и результаты находятся вне Git.

Проверки: совпали все 164 среза и 1551 страница результатов виджетов — значения, строки,
серии, форматы и выделение. После перезапуска PostgreSQL/backend восстановились граф,
дашборды и 55 результатов. Через UI проверены шесть экранов, переходы таблица/KPI,
перезагрузка, обе темы и три языка, поиск итоговой формулы, изменение и отмена.
Полные наборы: 360 backend-тестов, 121 frontend-тест; PostgreSQL, линтеры, типизация,
согласованность OpenAPI и production build проходят. Восемь браузерных сценариев проходят.

## Что действительно изменилось

| Признак | Прежний проект | Новый проект | Вывод |
| --- | ---: | ---: | --- |
| Узлы | 168 | 225 | +34%; больше элементов для автора |
| Связи | 172 | 321 | +87%; сложнее поддерживать полный граф |
| Расчётные столбцы | 27 одиночных операций | 27 выражений + 27 добавлений поля | Формула и её применение разделены явно, но нужна дополнительная настройка |
| Bar Chart | Таблица + выбор двух полей | Таблица + два полевых провода | Происхождение видно на холсте; подключений больше |
| KPI | Табличный вход + выбор поля | Явный скаляр, при необходимости контекст перехода | Граница «таблица → одно значение» проверяется; добавляется шаг |
| Обзор | Уже существовали группы | 7 составных блоков + книга | Не следует приписывать новому режиму само наличие группировки |

**Наглядность локального расчёта улучшилась:** подключённые поля, типы и границы строк
явные; можно проследить зависимость, раскрыть блок и смотреть выбранный результат.
Формулы a/b/c избавляют от ввода технических идентификаторов полей, но требуют читать
подписи соединений. Сам язык формул и смысл знаменателей знать по-прежнему нужно.

**Наглядность всего проекта улучшилась ограниченно:** большие блоки скрывают сложность,
а не устраняют её. В подготовительном блоке 80 нод и 20 публичных выходов. После
раскрытия понадобится поиск и перемещение по холсту. Два независимых просмотра A/B
полезны для проверки, но не являются автоматическим сравнением строк.

В ходе браузерной проверки найден и исправлен дефект поиска: раскрытие блока через
поиск сбрасывало масштаб найденной ноды до всего графа. Теперь найденная карточка
остаётся в читаемом масштабе. При «Вписать граф» подписи большого общего графа
по-прежнему слишком малы; это ограничение обзорного режима, а не доказательство удобства.

**Ускорение работы человека не измерено.** Участники по операторскому протоколу ещё
не проходили задания. Число нод, автотесты и время скрипта не заменяют этот замер.
Для первой сборки большого графа новая версия может быть медленнее из-за дополнительных
проводов и скалярных границ. При отладке конкретной зависимости полевые связи могут
помочь, но размер выигрыша сейчас неизвестен. Заявлять «в два раза быстрее» оснований нет.

## Следующие улучшения по выявленным трудностям

1. Мастер «Добавить вычисляемое поле»: выбрать поля по именам, задать выражение и имя;
   создать выражение, табличное применение и связи одной отменяемой операцией. Реальные
   узлы остаются редактируемыми; ручное создание проводов не должно быть обязательным.
2. Мастер KPI из выбранного результата: предложить явные варианты «ровно одна строка»
   и «сумма», показать различие, создать нужные узлы и связи. Никакой скрытой агрегации.
3. Упростить внутренний обзор больших блоков: расположение по зависимостям, выделение
   только пути выбранного результата, понятные названия публичных выходов по полям.
   Проверить на реальном подготовительном блоке, а не только на маленьком демо.
4. Провести задания из `UX_OPERATOR_PROTOCOL.md` с 3–5 аналитиками: время, успешность,
   ошибки, подсказки и сложность. До такого сравнения статус — «функциональнее,
   местами нагляднее; ускорение не подтверждено».

Это следующий приоритет удобства, не утверждение о выполненной реализации мастеров.
