# U5: копия проекта и проверка удобства

## Рабочая копия

Проект **«Анализ услуг — удобный конструктор (U5)»**:

- [Общая сводка в режиме просмотра](http://localhost:3000/projects/2173f33a-aa46-46af-9a19-b720de4fd036/dashboard?dashboard=851af11b-2392-4436-b3c6-cb88ab2a2c14&mode=view).
- [Редактируемый граф](http://localhost:3000/projects/2173f33a-aa46-46af-9a19-b720de4fd036/workflow?workflow=1faead6b-91bc-45f5-ad34-e68ea1b81a5b).

Это локальные ссылки текущей установки. Исходный проект сохранён отдельно и не изменён.
У копии собственные ID проекта, источника, графа, узлов, рёбер, дашбордов и виджетов.
Ссылки на вычисляемые поля и переходы переназначены. Расчётные цепочки сохранены.
Копирование выполнено тестовым инструментом через штатные API, без редактирования БД.
Это не новая пользовательская функция импорта или дублирования произвольных проектов.

168 узлов распределены по семи группам: подготовка и общие расчёты плюс ветки шести
дашбордов. Группы определены по фактическим зависимостям. В интерфейсе можно раскрыть
группу, найти её узел, изменить название, формулу или конфигурацию. Размещение графа,
переименование общей группы и шаблоны размещения дашбордов применены через интерфейс.
Из дашборда перейдите в редактирование и используйте «Открыть расчёт» у нужного виджета.
В двух селекторах услуг настроено отображение названий. В URL и условиях графа по-прежнему
передаётся числовой ID исходной строки; повторяющиеся названия не объединяются.

## Техническая приёмка

Перед копированием сохранены `.backups/u5-before.dump` и `.backups/u5-sources.tar`.
SHA-256 локального Excel совпал с одним сохранённым исходным артефактом. Журнал копирования
и исходный снимок находятся в `.backups/ux-project-copy.json` и
`.backups/ux-original-snapshot.json`. Все эти файлы исключены из Git.

Проверяются структурная эквивалентность расчётов и навигации, независимость ID и все
результаты виджетов в 164 срезах: сводка, 4 класса, 36 услуг, 3 вида затрат,
12 сочетаний вида и класса, 108 сочетаний вида и услуги. Сравнение с исходным сохранённым
проектом точное после нормализации ID копии и ревизии; страницы таблиц не пропускаются.
Исходный проект ранее прошёл сверку с opop_bi. Здесь проверяется эквивалентность копии,
а не повторный независимый запуск формул opop_bi для каждого показателя.

Результат технического этапа: **164 среза и 1551 результат виджетов совпали**. После перезапуска
восстановились граф, шесть дашбордов и 55 результатов на выбранных срезах. Проверены три языка,
обе темы и переход внутри копии. Последующая настройка названий услуг отдельно проверена на
18 затронутых виджетах и повторным перезапуском. 82 frontend-теста и 35 общих браузерных
сценариев проходят; оба новых сценария U5 выполнены отдельно. Подробности: [QA](QA_REPORT.md).

Проверка сохраняет контрольную точку после каждого среза. Возобновление допускается явно
и только при совпадении снимков обоих графов, дашбордов и определений срезов. После замены
backend или исходных артефактов запустите свежую сверку без флага возобновления.

Команды из `frontend` (PowerShell; БД и приложение уже запущены):

```powershell
$env:NODEBI_UX_COPY='1'
npx playwright test e2e/ux-project-copy.spec.ts
$env:NODEBI_UX_COPY='0'
$env:NODEBI_UX_COPY_PARITY='1'
$env:NODEBI_UX_COPY_RESTART='1'
npx playwright test e2e/ux-copy-parity.spec.ts
```

Журнал копии предотвращает создание дубликатов. Если копирование оборвалось, сначала
проверьте сохранённый журнал и фактические объекты; `NODEBI_UX_RESUME_COPY=1` разрешает
продолжить заполнение уже созданных дашбордов. Он не восстанавливает оборванную загрузку
источника или создание графа. `NODEBI_UX_RESUME_PARITY=1` разрешает продолжить сверку.
Не запускайте тесты, перезапускающие БД, параллельно с этой приёмкой.
Контрольная точка полной сверки предшествует настройке названий услуг. Для свежей полной
сверки текущей копии не устанавливайте `NODEBI_UX_RESUME_PARITY`: защита снимка справедливо
отклонит старую контрольную точку после изменения конфигурации селекторов.

## Проверка с операторами — ещё не выполнена

Используйте [протокол U0](UX_OPERATOR_PROTOCOL.md) и
[шаблон сырых результатов](UX_OPERATOR_RESULTS_TEMPLATE.csv). Нужны 3–5 аналитиков,
не участвовавших в реализации. Для заданий с изменением данных выделяйте отдельную копию;
не меняйте исходный эталон и проверенную копию во время автоматической сверки.

Для каждого задания сначала фиксируйте самостоятельный результат, затем помощь ведущего.
Сохраняйте неверные ответы и незавершённые задания, а не только успешные попытки. Если
базовые измерения до изменений не проводились, измерьте их на отдельной установке прежней
версии (`8c829a3`, с отдельной копией БД и файлов): сравнение новой версии с воспоминаниями
оператора не доказывает ускорение. Старую версию нельзя запускать поверх рабочей БД.

Автотесты не заменяют это исследование. Утверждение об ускорении на 40% пока не подтверждено;
U0 и человеческая часть U5 остаются незавершёнными.
